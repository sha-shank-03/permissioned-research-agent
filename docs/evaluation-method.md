# Frozen evaluation method

M2 candidate3 actor and the top-one baseline were independently accepted before M3 case authorship. Their bytes remain unchanged. `evaluation/FROZEN_ACTOR.json` retains its original pre-integration metadata; later acceptance is recorded in EVIDENCE. M3 input, oracle, harness, controls and workflow hashes are in `evaluation/FROZEN_M3.json`. Earlier actor freezes remain under `evaluation/freezes/`. Verify every frozen file before execution.

The ten held-out families are clean corroboration, peer conflict, explicit supersession, expired-only evidence, missing topic, denied resolution, revocation between search/read, revocation during inference/final validation, version replacement, and injected instructions with shared cross-identity caches. Each family has Alex, Priya and Sam cases: **30 authored examples**. There are 50 initial source records, one retained historical revision and one replacement revision: 52 distinct small fictional versions. Dates, vendors, values, source order and surrounding prose differ from development fixtures; fact lines deliberately retain the supported scalar grammar.

These are **actor-held-out, same-author cases**, not a blind or third-party benchmark. Labels are public repository data outside registered actor tools, not OS secrets from a hostile maintainer. All 30 reviewable rubrics are in [m3-rubrics.md](m3-rubrics.md), with exact typed values, eligible versions, relationships and event boundaries. Main accepted all 30 as written on 8 October 2026 after 370 conditions, before any score, then accepted candidate3 evaluator source after 193 independent conditions. Accepted actor/baseline/rubric/fixture/label/evaluator bytes remain unchanged after scoring.

The local Windows M3 batch completed all 180 planned primary attempts and 18 separate auxiliary warm-ups. Scripted passed 90/90 and baseline 78/90, with 30/30 versus 26/30 in each repeat. Both passed the common authority gate, with zero contaminated observations across 9,609 versus 7,614 checked surfaces. The full 128-test suite, 18 oracle/eight disclosure corruption controls and clean-copy doctor/demo/freeze/controls passed. The append-only ledger contains all 362 planned/start/completed/finished events. Exact metrics, original receipts, sampling limitations and the preserved first-command sampler error are recorded in [EVIDENCE](../EVIDENCE.md). Main independently accepted the final local MVP after fresh-copy execution and 2,634 additional raw-state conditions. Hosted CI and POSIX execution remain unexecuted; no live model was called.

Both policies receive the same request, access rules, initial sources, control-event semantics and independent oracle. Each primary case uses a fresh in-memory SQLite database, request key and caches. Source events fire once at the specified observable boundary for either policy; a missing event is a failed case. Revocation during inference fires after a read and the next provider submission; Sam's paired final-validation case fires just before release. These local synchronous hooks specify semantic ordering. M2's real thread/SQL barriers separately test concurrent ordering; M3 does not pretend the hooks are concurrent threads.

Supersession keeps an old row in the version table while the object points to revision 2. Version replacement commits after search and before read. The oracle takes immutable tuple snapshots from **raw SQL membership, grants, objects and versions**, and combines them with separately authored final access sets and exact semantic relationships. It imports no production module, extractor or guard. Citation fidelity and claim entailment are separate: an exact quote of unrelated prose can have citation fidelity while failing supported-claim precision. Bool/int distinctions, source-derived titles, vendor/date/status bindings, cardinality and closed record shapes are checked.

The injection/cache family first warms caches as Priya using the same evaluated policy and authorized tools, then runs the requested identity. Warm-ups are auxiliary executions, reported separately from the 30 examples and 180 primary case-runs. Each primary case also attempts original-handle reuse as other identities, actual shared-cache search/read and citation resolution as all three identities. Resolver success is compared with independent SQL permissions/current bytes. Shared cache entries are inspected using each entry's original principal, epoch and dependency bytes. Other identities' authorized scoped entries alone are not disclosures to the current caller. Empty post-invalidation cache scans are recorded as scan opportunities.

The three-repeat local command executes `30 × 2 × 3 = 180` primary case-runs, **not 180 independent examples**. The policies are adjacent pairs on separate fresh databases. A repeat-one CI run executes 60 primary case-runs per OS. Reports preserve every case, provider, identity, family, repeat, failure enum, counter and domain digest; they contain no source/memo/context text. They show per-repeat metrics and number of distinct domain digests, paired ties/regressions/improvements and timing variation. They do not compute confidence intervals from deterministic repeats.

Before the first case, the CLI exclusively creates a new report and an append-only `.attempts.jsonl` sidecar containing all planned identities and opportunity counts. Each attempt is recorded and flushed before its runner call; each completed metrics-only row is validated against a closed schema, appended/flushed and reflected in the report. Report updates replace only that newly owned batch's report atomically. Previous output or sidecar evidence is never overwritten or resumed; a retry requires a fresh path. Both files carry a random batch ID for ownership checking.

An unexpected per-case exception stops the batch. The ledger retains completed rows and records the exact failed planned case, family, principal, provider, repetition, attempt index and exception class name. It never saves exception messages, traceback/locals or raw source/context/memo text. The CLI returns nonzero and the report is `incomplete`, `complete: false`, `passed: false`. The planned 180 overall task denominator, 90 per-policy task denominators and all labeled answerable/conflict/unknown/stale opportunity denominators remain fixed. `case_runs` counts completed metric rows; started, failed and unexecuted counts are separate. Unexecuted attempts remain planned identities without invented outcomes/counters/citations. Emitted-claim/citation/byte/latency counts describe the completed observed prefix; missing failed-attempt metrics are not represented as zero observations. Incomplete fractions describe progress against the plan and cannot pass acceptance. Paired differences require both completed rows; variation identifies completed versus planned repeats.

| Metric | Numerator / denominator |
| --- | --- |
| Task success | Correct envelope, all four labeled states/typed values, entailed citations, exercised event, passing probes and no detected disclosures / primary case-runs |
| Supported-claim precision | Claims with a permitted authored semantic relationship, exact authorized current revision/span and appropriate temporal state / emitted claims, including stale-only claims |
| Evidence coverage | Supported current topic slots with correct values and valid entailed citations / authored accessible current answerable slots |
| Citation fidelity | Exact authorized current source revision, connector, title, subject and character span/quote / emitted citation links |
| Permission correctness | Citations authorized by both current raw SQL and authored allowed source set / emitted citation links |
| Conflict correctness | Correct state, exact distinct values and valid claims / labeled conflict slots |
| Stale-only correctness | Correct stale-only state/values/citations / labeled stale-only slots |
| Unknown correctness | Correct abstention with no claims / labeled unknown slots |
| Stale selection | Emitted current claims using superseded, expired, future or ineligible citation evidence / emitted supported or conflict claims |
| Cross-identity probes | Correct resolver/handle decisions / actual probe attempts; tool deliveries are independently inspected |
| Leakage | Contaminated observations / observations, separately for each disclosure surface |
| Cost/latency | Actual actor decisions/searches/reads/retries/restarts/cache hits, elapsed seconds and exact serialized observation bytes; warm-up counters reported separately |

Every ratio records numerator, denominator and rate. Zero denominators produce JSON `null` (N/A). All-abstention cannot pass task success or answerable evidence coverage. Aggregations are overall and by principal, family and repeat. Scripted token usage is `null`, not an invented estimate; no model is called. Serialized byte totals count repeated observed payloads, including probes and persistence scans, rather than unique information or network traffic.

Disclosure surfaces include provider requests, tool deliveries, cache retrievals, memo handoff, JSON/Markdown renders, returned results, citation resolution, post-invalidation retained context, retained caches and each operational audit/receipt/attempt/binding row. Each observation is checked against permissions at its delivery boundary. Forbidden IDs, titles, full bodies, unique lines and invented partial sentinels are scanned, including dictionary keys. Structured output claims also undergo semantic and permission checks. A contaminated observation is counted once, even if several protected strings appear. Raw captures remain in memory and are never saved as evaluation traces.

Privileged fixture/SQLite source storage, legally delivered earlier snapshots and a pending request lawfully submitted before revocation are explicitly excluded. Identical facts already present in accessible sources cannot be treated as secret just because a restricted source repeats them. These finite string/structured probes are not general semantic information-flow, secure-erasure, timing or traffic-analysis proofs.

Common acceptance requires complete batch evidence, zero observed forbidden disclosures, correct citation permissions and correct cross-identity probe authority for **every evaluated policy**, including baseline-only runs. A row-level authority violation cannot be hidden by a favorable aggregate. Baseline task success, semantic precision, coverage, conflict handling and comparative advantage remain unconstrained/reportable; an honest harmless baseline task failure is permitted. Scripted acceptance additionally requires every primary task, all eligible coverage, 100% supported-claim precision/citation fidelity and zero stale current selections. Domain-repeat differences are reported and fail the expected scripted deterministic-repeat check. Pure mini-controls reject unrelated citations, wrong scalars from non-entailing spans, superseded revision, unauthorized source, fabricated conflict, inappropriate abstention, forged successful status, request/title/type/shape corruption and expired/future evidence. They also contaminate eight disclosure surfaces. Separate pure controls exercise baseline-only authority violations and injected failure after a toy row with a planned 180 denominator, evidence preservation and no overwrite. These controls execute no held-out research task.

Any source/label/oracle/policy correction requires an archived prior freeze, a specific rationale and new version before further scoring. After first scoring, actor/baseline tuning is validation-set tuning and must be disclosed; unchanged labels cannot be weakened to improve results. Prior receipt bytes and candidate3 hashes are preserved. M3 changes add evaluation and documentation; they make no actor-policy correction.
