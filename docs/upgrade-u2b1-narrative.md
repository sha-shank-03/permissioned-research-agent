## Draft boundary

Seven records cover hosting region, SSO, onboarding time, support response,
conditions, dependencies and exceptions. Each record proposes supported,
conflict, stale-only or unknown state. State labels remain proposals pending
semantic review; an empty unknown record does not pass a coverage gate.

At most12 atomic claims are allowed across all records, at most280 Unicode
characters each, with one/two exact quotes of at most1024 characters. Quotes
must refer to opened identity-bound handles and match source revision, SHA256,
Unicode character offsets and literal text. Unknown records have no claims;
conflict proposals need at least two claims with distinct accessible source
identities. Current states require current authored effective/review intervals;
stale-only requires expired evidence; future-effective quotes are rejected.
These checks cannot establish that two paragraphs contradict or support prose.

The renderer derives source IDs/citations/titles/dates from checked source records and
escapes source/model strings as literal HTML text. It creates no source URLs or
clickable model-selected links. The model cannot submit approval, identities,
credential selectors or review scores. Every released draft remains
`needs_review`; semantic approval, support, qualifiers, causality, conflict
resolution, required-fact coverage and reviewer agreement remain null.

A well-formed quote from a permitted source can still be unrelated to its claim.
The omitted-security-approval-qualifier test intentionally shows valid quotes
with unsupported prose and preserves pending independent review. The runtime
does not pretend that span validity proves meaning. Unknown-topic completeness,
atomicity, entailment, incompatible obligations, missing qualifiers, causal
claims and all-abstention coverage require the independent rubric below.

## Shared provider and fixed comparison

Both policies use `NarrativeProvider`, the same native function schemas,
explicit synthetic model, source tools and configuration. Native calls have
unique IDs, assistant/tool correlation and actual observations. Fixed policy's
controller-produced observations are identified as controller evidence rather
than fabricated model tool calls. One malformed proposal may receive one repair
with an error enum; no automatic HTTP retry or model fallback occurs.

The fixed policy performs six predeclared searches: hosting region; SSO support;
onboarding lead time; priority support response; conditions/qualifications;
dependencies/exceptions. It ranks accessible returned current-version sources
by date eligibility, query matches and a stable private identity tie-breaker,
then round-robins connector/folder groups, selecting at most8. Current-date
sources precede stale sources; stale sources may remain only to report stale-only
evidence. Future-effective sources are excluded. No answer labels are consulted.
It makes one synthesis call and at most one repair; the model cannot add searches.

Ceilings for both policies:12 provider requests,6 logical searches,8 reads,
48 KiB serialized context,64 KiB provider response,16 KiB action and draft,
2048 synthetic output-token ceiling and120 seconds total with cleanup reserved.
Local logical search fans out over the two existing ACL-filtered connectors;
its backend fan-out count is reported separately and is identical for both
policies. Drive GET budgets/rechecks retain the accepted U2-A bounds. No context
is silently truncated and no denied source is used to pad source selection.

Counters and repair allowance survive the single permitted whole-context reset.
Fixed collection does not obtain a second six-search allowance after revocation:
if the remaining cumulative budget cannot recollect, it fails closed. No numeric
quality or positive-uplift result is claimed from this comparison seam.

## Authority, invalidation and remote race

Principal/vendor/date are trusted request inputs outside model arguments. The
local projection reuses actual SQL ACL-first `ScalarTools`; disclosure submit
acknowledgement and caller release occur inside the same SQL write gate.
Response collection remains outside the gate. Every retained search/read
dependency is rechecked before provider disclosure, after collection and before
final handoff. Revocation/version changes discard the entire observations,
handles and provider history; counters and used call IDs are not reset.

The Drive seam accepts the unchanged Drive adapter only with explicit native
loopback or an authored non-network transport. Production-origin transport and
principal substitution fail before dispatch. Version/hash/freshness/access
checks remain mandatory; there is no cross-run remote cache. The fake subject
numbers and placeholder token are authored test data, never OAuth proof.

Drive rechecks cannot atomically order a remote ACL commit with Gateway send or
caller release. Permission propagation/index lag and the inter-request race
remain. Already disclosed observations and caller snapshots cannot be recalled
or securely erased. The future genuine delegated-user test still needs the
approved loader, three accounts, pinned mappings and owner/manual fixture
control-plane actions; none were performed or replaced by privileged access.

## Independent semantic review rubric — no scores recorded

Reviewers receive the released draft and independently authorized current raw
sources, plus a separately authored required-fact/relationship rubric. The actor
does not see acceptance labels or serve as its own ground-truth judge. For each
claim, a reviewer records support (entailed/unsupported/ambiguous), exact
qualifiers, dependencies/exceptions, contradiction handling, temporal framing,
causal support and criticality, with cited rationale. A valid unrelated quote,
omitted condition, unsupported causal relation or fabricated critical claim
must be recorded as a failure despite passing the runtime span guard.

At the task level, record eligible required facts and correctly covered facts,
missing obligations, over-abstention, conflicts/stale-only/unknown handling and
any cross-principal leakage. Keep emitted-claim and eligible-fact denominators,
failures and ambiguous cases visible. Use blinded policy output where feasible;
record independent reviewer identities/adjudication and agreement only when
actually obtained. Pending/null fields are not zero or successful scores.
